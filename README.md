## 团队待审

首页输入 GitHub 用户名，可按 Issue 负责人、报告者、关联 PR 作者、当前被请求 Review 四种明确关系筛选。普通交叉引用与关闭引用分开标记；账号关系来自公开字段，不推测团队归属，不将评论者当作负责人。PR 作者和 Review 请求的补充采集时间在数据质量中单独显示。

按 issue 去重汇总候选，分为“建议优先核对”“有关闭线索，需本人确认”和“仍有明确未完成事项”。默认展示前两组；未完成事项可单独进入。分组用于人工处理顺序，不代表已证明可以关闭；用例与验证状态单独说明证据完整性。候选原因包括关闭引用 PR 已合并、失败清单已有处理结论、受限通过线索、删除线标记、重复主记录和剩余任务的明确转移。父子、来源和其他用例的相关引用单独展示，不据此生成关闭候选。

正文处理标记支持无编号列表、复选框、段落、标题和表格。未勾选子任务保留，勾选任务下的说明不重复算未完成；代码、引用、环境说明、代理流程清单和正式测试清单不混入一般任务。部分划线或范围不明确时只作为待确认线索；勾选、划线不直接代表修复。正文事项可按文字搜索，并筛选未标记处理、部分划线或已标记处理，保持原文行号及附属说明。

逐项区分普通通过记录、调整条件后通过、绕过问题后通过、修复 PR 已合并、skip / xfail、测试删除替换、转移跟踪、删除线和未知；展示人工讨论、GitHub Actions nightly 和 PR 状态证据。删除线和 skip 不直接代表缺陷解决，标题声明数量不一致的清单保留覆盖未知，目标 release、间歇性失败与未完成反馈需单独确认。批次报告与底层遗留缺陷分开处理，页面不执行关闭操作。

清单直接展示相关人员、PR 作者、候选理由、未完成事项及待确认条件；优先显示关闭引用，按账号筛选时优先显示本人参与的 PR。支持复制含仓库编号、人员关系、理由与缺失条件的审核摘要，不向外部发送消息。CSV 保留人员与 PR 的文本摘要。

审查视图可筛选、分享、撤销、排序和导出 CSV；详情中的用例支持测试名、路径及迁移标识搜索，按未完成事项、配置待确认或具体状态筛选，证据按批次展开。配置未核对的通过记录保持待确认；详情保留纯文本 workflow、run 编号、分支、commit 与评论记录标识，逐项摘录包含对应测试名。

## 桌面工作台

- 默认进入团队待审；全部 Issue 和整体分布保留独立入口，完整快照指标位于整体分布，图表可收起。
- 筛选器可搜索和多选，同维度 OR、不同维度 AND；支持浏览器后退/前进、撤销以及分享当前视图。
- 清单突出编号、标题、模块、负责人、Milestone、下一步动作、待核对材料、关闭引用 PR 和更新时间；原报告明确的 release 目标分支单独展示；详情提供测试入口、环境及原文证据。
- 整体分布按全部 issue 计算，矩阵支持数量和模块内占比，未知单独显示为中性灰。
- 负责人状态与阻塞证据分开；Unexpected success 为测试预期需核对；not implemented 不直接归类为新功能请求。
- 关闭引用 PR 与普通引用分开；代码块保留缩进复制，正文及评论按需展开，评论每批 20 条。
- “有合并记录，无进行中关闭引用”与“至少一个关闭引用 PR 已合并”分别统计；页面说明两组集合的包含关系。
- 构建问题核对参数、编译器与合并后构建结果；人工复测核对环境、版本 / commit、命令及超时条件；CI 记录核对 workflow 与分支。
- 自动分析按正文中的生成标识识别，人工账号发布也不视为人工确认，建议单独展示。
- 数据质量展示材料覆盖率、待定位分类与验证评论线索；人工更正保留核查人、日期和依据。

`index.html` 内嵌数据、样式、脚本，无外部 URL、资源、backlink 或运行时网络请求。下载该文件也可以离线查看。当前仅针对桌面使用优化。

## 重建与更新

需要 Python 3。使用已发布的地址清理快照重建：

```sh
python tools/update_report.py --cached data/source-snapshot.json --output-dir .
python tools/verify_report.py index.html data/source-snapshot.json
python -m unittest discover -s tools -p 'test_*.py'
```

获取最新快照还需要已登录的 GitHub CLI：

```sh
python tools/update_report.py --output-dir .
```

保存公开快照时，外部地址会被移除；GitHub issue / PR 引用保留为仓库名和编号，Actions 引用保留为运行编号，以支持无链接的证据重建。完整评论保留 Markdown，以解析结果表格和区分引用。PR 关联合并 issue 时间线与 PR 关闭引用的反向索引，并独立校验。

生成器、模板、规则、核查配置和检查脚本都在 `tools/`，详细说明见该目录 README。发布源为 `main` 分支根目录；提交新的 `index.html` 后 Pages 会重新部署。没有自动定时更新任务。

公开线索和自动分类不代替当前复现、根因定位或严重度判断。报告中的版本是报告环境；只有经人工核查的验证记录才作为已确认验证结果。
